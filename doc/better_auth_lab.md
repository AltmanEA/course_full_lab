# Лабораторные работы — Better Auth (Fullstack)

## Лекция 1

### bauth01 — Инициализация Better Auth

Задача вводит инфраструктурный модуль аутентификации. Студент создаёт отдельный auth-модуль и изолирует конфигурацию Better Auth от бизнес-логики. Формируется понимание auth как отдельного слоя, не связанного напрямую с router или UI.

---

### bauth02 — Интеграция с PostgreSQL

Задача подключает Better Auth к существующей базе данных через Drizzle ORM. Студент осваивает корректное связывание auth-слоя и persistence-слоя без нарушения архитектурных границ.

---

### bauth03 — Таблицы users и sessions

Задача вводит структурную модель хранения пользователей и сессий. Студент понимает связь auth-пользователя и таблиц базы данных и закрепляет роль схемы как части инфраструктуры.

---

### bauth04 — Регистрация пользователя

Задача реализует серверную регистрацию пользователя через API Better Auth. Студент осознаёт, что создание пользователя — это инфраструктурная операция, а не бизнес-логика приложения.

---

### bauth05 — Login и создание session

Задача вводит процесс аутентификации и создания session. Формируется понимание session lifecycle и роли cookie в хранении идентификатора сессии.

---

### bauth06 — Получение session на сервере

Задача демонстрирует получение текущей session в серверном окружении Next.js. Студент осваивает извлечение пользователя без использования глобальных импортов.

---

### bauth07 — Передача user в tRPC context

Задача интегрирует auth с DI-моделью через расширение context. Студент передаёт пользователя в tRPC через createContext и закрепляет принцип dependency injection.

---

### bauth08 — Session expiration

Задача добавляет проверку истечения сессии. Студент понимает модель абсолютного срока действия и роль expiration в безопасности.

---

### bauth09 — Logout и инвалидация session

Задача реализует корректный logout. Студент осваивает механизм удаления или инвалидирования session и понимает завершение жизненного цикла.

---

### bauth10 — Полный lifecycle аутентификации

Финальная задача лекции объединяет регистрацию, login, получение session и logout в единую модель. Формируется целостное понимание инфраструктурного слоя аутентификации.

---

## Лекция 2

### bauth11 — protectedProcedure

Задача вводит централизованную защиту процедур. Студент реализует protectedProcedure и формирует архитектурную модель проверки авторизации на уровне router.

---

### bauth12 — currentUser query

Задача реализует процедуру получения текущего пользователя через context. Студент закрепляет принцип использования injected user без прямого обращения к auth.

---

### bauth13 — Расширение user моделью роли

Задача добавляет поле role в таблицу users. Студент подготавливает инфраструктуру для RBAC и осознаёт расширяемость модели пользователя.

---

### bauth14 — adminProcedure

Задача вводит RBAC через композицию protectedProcedure и проверки роли. Формируется модель role-based доступа на уровне API.

---

### bauth15 — ADMIN-only mutation

Задача применяет adminProcedure к конкретной mutation. Студент закрепляет практическое использование RBAC в прикладной логике.

---

### bauth16 — Ownership check в router

Задача реализует проверку владения ресурсом по userId. Студент осваивает различие между ролью и принадлежностью ресурса.

---

### bauth17 — Ownership в access layer

Задача переносит проверку владения в access-layer. Студент закрепляет принцип тонкого router и корректного разделения ответственности.

---

### bauth18 — Разделение UNAUTHORIZED и FORBIDDEN

Задача формирует корректную семантику ошибок доступа. Студент осваивает различие между отсутствием пользователя и недостаточностью прав.

---

### bauth19 — DI-гарантии в router

Задача проверяет архитектурную чистоту: router не импортирует auth напрямую. Студент подтверждает соблюдение dependency injection.

---

### bauth20 — Полный защищённый mutation-flow

Финальная задача лекции объединяет protectedProcedure, RBAC и ownership в едином сценарии защищённой операции. Формируется комплексная модель защиты API.

---

---

Задача реализует фиксированное время жизни session. Формируется модель абсолютного истечения.

### bauth25 — Sliding expiration

Задача вводит обновление срока действия при активности пользователя. Студент осваивает механизм продления session.

### bauth26 — Session rotation

Задача реализует создание новой session при повторной аутентификации. Формируется модель защиты от фиксации сессии.

Задача добавляет проверку CSRF-токена. Студент осознаёт необходимость дополнительной защиты при использовании cookie.

### bauth28 — Middleware Next.js vs tRPC

### bauth29 — Обработка отсутствующего cookie

---

### bauth30 — Production-ready security конфигурация

Финальная задача лекции объединяет cookie-настройки и expiration в целостную production-конфигурацию.
